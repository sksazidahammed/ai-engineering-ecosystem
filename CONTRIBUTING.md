# Contributing to the Directory

**Guidelines version:** 1.0  
**Last updated:** 2026-11-12 17:39 IST (UTC+05:30)

This directory accepts submissions of GitHub repositories, official documentation, skills, plugins, MCP servers, CLI tools, applications, frameworks, PDFs, screenshots, and other useful references.

## Submit a project

Include as much of the following as you can:

1. Project name and official URL.
2. What problem it solves.
3. Intended category and actual artifact type, if known.
4. Which coding agents, platforms, or runtimes it supports.
5. Why it is useful and what makes it different.
6. Known installation, pricing, API-key, or account requirements.
7. Any security or privacy concerns you have noticed.

A link alone is acceptable; missing details will be researched rather than guessed.

## How entries are processed

1. Identify the canonical upstream project.
2. Check the README and official documentation.
3. Confirm the project type and category.
4. Review license, maintenance signals, dependencies, and security implications.
5. Merge duplicates and preserve alternate names where useful.
6. Add the entry with an explicit verification status.
7. Update the master catalogue, category page, and changelog.

## Quality rules

- Do not submit private credentials, API keys, access tokens, or personal data.
- Do not describe a project as official unless the upstream owner confirms it.
- Do not treat a fork as the canonical project without evidence.
- Do not claim a project is safe, production-ready, or actively maintained without evidence.
- Report broken links, changed ownership, archived status, and security issues with supporting sources.

## Reader note

Inclusion means the project has been catalogued, not endorsed. Users remain responsible for reviewing source code, permissions, licenses, and operational risks before use.
